# 附錄 A 量測協定與配置

> 附錄收集主文用到但會打斷敘述的「操作細節」：三協定逐步指令、主表 config 範例、
> 工具鏈用法、計數器判讀。第六章數據皆由此處的固定程序產出，保證可重現。

## A.1 三協定量測操作細則

以下 fio 參數全平台共用：
`--direct=1 --ioengine=libaio --iodepth=32 --numjobs=1`。

### A.1.1 P1 排水態（steady-state）

目的：灌滿 NVMe SLC 帶後量 TLC 穩態；可重現、不受 SLC 暫態干擾。
排水卷與量測卷**可以分開**——排水態的關鍵是「SLC 已耗盡」，故先以排水卷灌滿
SLC（寫入量 ≥64 G、丟棄），再建量測卷歸零計數量測（主表 S4 用 20 G 卷、
疊碟表用 100 G 卷；卷容量只需能容納量測寫入，P1 量測寫入一律 16 G，故
量測卷較小、無需承載排水量）。

```bash
# 1) 排水卷（容量 ≥ 排水量）：先寫 ≥64 G（丟棄）灌滿 SLC
dmsetup create tv_drain --table "0 <sectors> tieredvol /etc/tieredvol/tv_drain.conf"
fio --name=drain --filename=/dev/mapper/tv_drain --rw=write --bs=1M --size=64G \
    --direct=1 --ioengine=libaio --iodepth=32
dmsetup remove tv_drain
# 2) 量測卷：建卷 → 歸零計數 → 寫 16 G（P1 的數據源）
dmsetup create tv_s4 --table "0 <sectors> tieredvol /etc/tieredvol/tv_s4.conf"
fio --name=meas --filename=/dev/mapper/tv_s4 --rw=write --bs=1M --size=16G \
    --direct=1 --ioengine=libaio --iodepth=32
# 3) 驗分布
dmsetup status tv_s4
# 4) 讀 16 G
fio --name=read --filename=/dev/mapper/tv_s4 --rw=read --bs=1M --size=16G \
    --direct=1 --ioengine=libaio --iodepth=32
```

### A.1.2 P2 冷態（SLC-fresh）

目的：資料落在 SLC 帶狀的**最大**數值（快碟主導場景）；**不可重現**，只用於
定性對照（如 auto-weight 階梯）。

```bash
# 重開機（或等 ≥ 數分鐘讓 SLC 完全回充）後直接短寫量測
fio --name=meas --filename=/dev/mapper/tv_xx --rw=write --bs=1M --size=8G \
    --direct=1 --ioengine=libaio --iodepth=32
```

### A.1.3 P3 冷態＋60 s 空檔

目的：每輪之間空檔 60 s，讓 P3 Plus 的 SLC 回充，使冷態短寫**可重現**；主表
（S1–S3/MIR）使用本協定。

```bash
for size in 8 8 8; do
    fio --name=meas --filename=/dev/mapper/tv_xx --rw=write --bs=1M \
        --size=${size}G --direct=1 --ioengine=libaio --iodepth=32
    sleep 60   # SLC 回充空檔
done
# 三次取中位數
```

### A.1.4 4 K 小寫與 WC 對照

4 K（`< chunk_size`）小 bio 走 `-EAGAIN` 分支**繞過 WC**（4.2），故 4 K 量測即
「WC 關閉」的小寫路徑；測 WC 併塊價值時才需開關 `wc_enabled` 對照：

```bash
# (a) WC 併塊對照（W1–W4，wc_suite.sh；wc_enabled=1 vs 0）
echo Y | sudo tee /sys/module/tieredvol/parameters/wc_enabled   # 或 N
fio --name=wc --filename=/dev/mapper/tv_xx --rw=write --bs=4K --size=1G \
    --iodepth=1 --direct=1 --ioengine=libaio
# 最終 build tv_s2：wc=on 4K 612 MiB/s；wc=off 4K 500 MiB/s（修復前 14，見 6.5）

# (b) 4 K 隨機對照（6.4.2 表 6.12，B@x4）：4 K 繞過 WC、成本在條帶拆分
fio --name=rnd --filename=/dev/mapper/tv_xx --rw=randwrite --bs=4K --size=8G \
    --direct=1 --ioengine=libaio --iodepth=32 --numjobs=1

# (c) 4 K 小寫 vs LVM（6.4.1，8/13 舊拓撲 B@x1，2 G）：TieredVol 511 vs LVM 676
fio --name=sq4k --filename=/dev/mapper/tv_xx --rw=write --bs=4K --size=2G \
    --direct=1 --ioengine=libaio --iodepth=32
```

> 4 K 的「小寫贏/輸」結論依測試類型而異：順序 4 K 併塊（WC 開）TieredVol 勝；
> 隨機 4 K（繞過 WC）在 B@x4 下 +16% 勝、在舊拓撲 B@x1 下 LVM 快 ~1.32x
> （6.4.1/6.4.2、6.6 限制 4 已標註拓撲）。

## A.2 主表 config 範例（B@x4 + D 拓撲）
> 碟以 **by-id** 指定；權重為 DMI-aware 權重（3.3.3）。實際 by-id 依系統而定，
> 以下以佔位符表示。sectors 以 `blockdev --getsz <dev>` 取得。

### A.2.1 `tv_s2.conf`（A+B，權重 37:27，stripe 64 MB）

```ini
chunk_size = 1048576
segment.0.disks = /dev/disk/by-id/<A>, /dev/disk/by-id/<B>
segment.0.weights = 37, 27
segment.0.logical_begin = 0
segment.0.logical_end = <sectors_A_B_sizes>
```

### A.2.2 `tv_s3.conf`（A+B+C，權重 64:30:10，stripe 104 MB）

```ini
chunk_size = 1048576
segment.0.disks = /dev/disk/by-id/<A>, /dev/disk/by-id/<B>, /dev/disk/by-id/<C>
segment.0.weights = 64, 30, 10
segment.0.logical_begin = 0
segment.0.logical_end = <sectors_A_B_C_sizes>
```

### A.2.3 `tv_s4.conf`（A+B+C+D，權重 64:27:9:4，stripe 104 MB）

```ini
chunk_size = 1048576
segment.0.disks = /dev/disk/by-id/<A>, /dev/disk/by-id/<B>, /dev/disk/by-id/<C>, /dev/disk/by-id/<D>
segment.0.weights = 64, 27, 9, 4
segment.0.logical_begin = 0
segment.0.logical_end = <sectors_A_B_C_D_sizes>
```

### A.2.4 `tv_mir.conf`（A+B → mirror C，權重 37:27）

```ini
chunk_size = 1048576
segment.0.disks = /dev/disk/by-id/<A>, /dev/disk/by-id/<B>
segment.0.weights = 37, 27
segment.0.mirror_disk = <C>
segment.0.logical_begin = 0
segment.0.logical_end = <sectors_A_B_sizes>
```

## A.4 計數器判讀（`dmsetup status`）

範例輸出（卷 tv_s2 寫入 16 G 後）：

```
0 33554432 tieredvol
    w=37,27 c=1048576
    disk0: wr=10485760/0x280000000 rd=0/0
    disk1: wr=7340032/0x1c0000000 rd=0/0
    err=0 borrow=0 mirror_wr=0 mirror_rd=0 mirror_err=0
```

判讀規則：

- `wr=<ops>/<bytes>` 的 bytes 比例應等於權重比（37:27）；餘量 chunk 落入前段碟，
  屬預期（見 6.2.1）。
- `err` 必須為 0（完整性判據）；非 0 即代表 MISS/give-up/寫錯誤事件，需追查。
- `borrow`/`mirror_wr` 等計數用於專項測試（6.5）的觸發確認。

## A.5 安裝與載入

```bash
# 建置（核心模組；L1/L2 測試不需核心）
make            # 產出 tieredvol.ko
make test       # test_map + test_stripe_kernel（使用者態）
# 安裝
sudo insmod tieredvol.ko          # 或複製至 /lib/modules/... 用 modprobe
# 開機自動載入（scripts/install_boot.sh）
sudo cp tieredvol.ko /lib/modules/$(uname -r)/kernel/drivers/md/
sudo depmod -a
echo "tieredvol" | sudo tee /etc/modules-load.d/tieredvol.conf
# 建卷（config 見 A.2）
sudo dmsetup create tv_s4 --table "0 <sectors> tieredvol /etc/tieredvol/tv_s4.conf"
# 檔案系統
sudo mkfs.ext4 /dev/mapper/tv_s4 && sudo mount /dev/mapper/tv_s4 /mnt/tv
```

## A.6 故障演練（Rebuild / 壞碟處理）

**觸發 rebuild**：

```bash
sudo dmsetup message tv_s4 0 rebuild         # 依靜態映射重建 mirror
dmsetup status tv_s4                          # 觀察 mirror_wr/進度計數
```

**壞碟／壞區處理**：

```bash
# 查壞區（config 內的 badmap_<disk>=a-b,c）
cat /etc/tieredvol/tv_s4.conf | grep badmap
# 壞區重建（讀 primary → 寫 mirror，跳過壞塊）
sudo dmsetup message tv_s4 0 rebuild_badmap
# 確認 no-hang 且計數正常
dmsetup status tv_s4
```

**WC 斷電風險的因應**：需嚴格持久性時關閉 WC 再建卷

```bash
echo N | sudo tee /sys/module/tieredvol/parameters/wc_enabled
```

**借調驗證（borrow_verify.sh 之人工版）**：製造慢碟高負載 → 確認 `borrow`
計數上升 → `dmsetup remove`＋重建 → 確認 `.borrow` 載入、資料可讀。

## A.7 量測陷阱（被數據騙過的經驗）

1. **fio 會對不存在的 `/dev/mapper/<名>` 建普通檔**：若 `dmsetup ls` 顯示裝置
   不存在，fio 會在磁碟上建同名檔案——得到假讀（~5.5 GB/s）或假 ENOSPC。
   **先 `dmsetup ls` 確認裝置、`chmod 666` 後**才信賴 fio 數字。
2. **`dmsetup message` 的 result buffer 不印出**：讀計數/錯誤一律用
   `/sys/kernel/tieredvol/status`；它只反映 `tv_active_ctx`（最後 ctr 的卷），
   多卷共存時 per-disk 計數改用 `/proc/diskstats` 的 write-sector 增量驗證。
3. **多行 table 的 `dmsetup create` 不能用 `echo pw | sudo -S` 前綴**（stdin 被
   sudo 吃掉、table 只剩一半）——先 `sudo -S -v` 快取權限再直接 `sudo`；
   `dd` 從 pipe 讀只傳 64 KB（pipe buffer），大資料用檔案輸入。
4. **不 `pkill -9` 深佇列 direct I/O**：8/14 對兩個 1M/d32 libaio fio 執行
   SIGKILL 後 AHCI/SATA 控制器被 wedged（B85，附錄 B.7）——一律固定
   `--runtime` 讓 fio 自然結束。
