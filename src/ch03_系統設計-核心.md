# 第三章 系統設計（一）：架構、映射與模型

本章說明 TieredVol 的整體架構與數學核心。第四章說明進階機制與容錯（借調、寫入
快取、鏡像、併發、管理），第五章落地實作，第六章以實驗驗證。本節按
「架構總覽（3.1）→ 加權條帶化與確定性映射（3.2）→ 瓶頸模型與自動權重（3.3）→
測試架構設計（3.4）」的次序，每節依「動機 → 設計 → 數學/演算法 → 邊界案例與
不變式 → 設計取捨」展開。

## 3.1 系統架構總覽

### 3.1.1 設計目標

TieredVol 作為 dm target，須同時滿足以下目標（有些彼此拉扯，需權衡）：

**表 3.1 設計目標（G1–G7）**

| # | 目標 | 要求 |
|---|------|------|
| G1 | 確定性 | 同一邏輯位址永遠落同一碟同一位置；可重現、可驗證 |
| G2 | 低熱路徑成本 | 映射 O(1)、無共享鎖、可在 hardirq 等受限 context 執行 |
| G3 | 性能 | 整體吞吐接近瓶頸模型上界（權重匹配時 ≈ Σsolo） |
| G4 | 正確性 | 分布逐 byte 精確；`err=0`；讀寫序正確 |
| G5 | 動態平衡 | 慢碟暫時退化時可補償，但不破壞 G1 |
| G6 | 容錯 | 鏡像、重建、壞區、並發一致性命中同一 target |
| G7 | 可管理 | 單一 config 真相來源、CRC 驗證、計數器可查 |

### 3.1.2 三層結構

TieredVol 以 Linux Device Mapper 的 target 形式存在，掛載後成為一個邏輯區塊裝置。
整體架構分三層：

- **配置層（config / meta）**：單一真相來源 `/etc/tieredvol/<name>.conf`
  （INI 格式），描述碟清單、各碟權重、chunk 大小、segment 分段、鏡像碟、
  壞區記錄等；核心載入時以 CRC32C 驗證完整性（4.5）。
- **映射層（map）**：`tv_map_logical()` 以純算術把邏輯位址轉為
  `(disk, physical_offset)`，無鎖、無狀態、O(1)，任何 context（hardirq、
  kthread、io_uring worker）皆可安全呼叫（3.2）。
- **I/O 層**：寫入經平行拆分配置路徑（跨碟拆成 per-disk sub-bio）、單碟直接
   提交、可選寫入快取（WC）緩衝（4.2）；讀取走 DM 的重新映射拆分；鏡像（4.3）
   與錯誤處理掛在完成回呼上；權重借調（4.1）攔截慢碟高負載的整塊寫入。

![圖 F3 TieredVol 系統架構（figs/F3_architecture.svg）](figs/F3_architecture.svg)

> **圖 F3 說明**：上半為配置層與映射層（控制流、偶發）；下半為 I/O 層（資料流、
> 熱路徑）。計數器與完成回呼是第六章驗證的掛點。完整圖註見 4.5、5.7。

### 3.1.3 核心設計哲學

整個 driver 的地基是一張「邏輯位址 → (碟, 實體位址)」的**函數**，而不是一張表。
此函數無狀態、不查詢、不需重建索引，故 I/O 熱路徑上沒有共享鎖。所有動態性
（慢碟 offload）都以「在靜態佈局之上的**暫時例外**」實作（權重借調，4.1），
**不破壞映射的確定性**（G1 與 G5 的折衷）。任何會讓「同一邏輯位址在不同時間
落不同碟」的機制（如動態選碟 policy）都被排除——第二章已說明其歷史教訓。

```
  ┌──────────────┐
  │  /etc/tieredvol/<name>.conf  (INI + CRC32C)
  └──────┬───────┘
         │ ctr() 載入、驗證
  ┌──────▼───────┐
  │  meta        │   segment / weight / disk 清單
  └──────┬───────┘
  ┌──────▼───────┐   WRITE                    READ
  │  map()       │──► WC 緩衝 / 平行拆分配置 ──► DM 重新映射拆分
  │  tv_map_     │    （跨碟→per-disk sub-bio） │
  │  logical()   │◄── 完成回呼：計數/錯誤/標壞/  │
  └──────┬───────┘    mirror retry            │
         ▼                                     │
  disk0  disk1  …  disk n-1  （+ mirror disk） ┘
```

### 3.1.4 資料流與控制流

- **資料流（每筆 bio）**：`map()` → （WC 緩衝 或 直接）→ 平行拆分/單碟轉發 →
  實體碟 → `end_io()` 完成回呼（計數、錯誤處理、mirror retry）。
- **控制流（偶發）**：`message()`（切 policy、觸發 rebuild、查 mirror）、
  `status()`（計數器）、deferred work（WC 逾時 flush、mirror retry、rebuild
  kthread、borrow 持久化）。
- 計數器（每碟 `wr=/rd= ops/bytes`、`err`、borrow/mirror 計數）是第六章
  正確性驗證的關鍵介面。

## 3.2 加權條帶化與確定性映射

### 3.2.1 問題與定義

給定 n 顆碟、權重向量 W=(w₁,…,wₙ)、chunk 大小 c，欲把邏輯空間切成等長 chunk，
依權重比例分配到各碟，使長寫的分布比例精確等於權重比，且映射滿足三性質：

- **P-確定性（Deterministic）**：相同邏輯位址永遠落同一碟同一位置。
- **P-O(1)**：常數時間的數學運算完成（無查表、無索引）。
- **P-精確（Exact）**：每個邏輯 byte 恰好屬於一顆碟（無洞、無重疊）。

### 3.2.2 條帶與段（Stripe & Segment）

一次權重分配循環內，各碟依權重各拿 wᵢ 個 chunk，共

```
stripe_size = Σᵢ wᵢ × c          … (3.1)
```

把邏輯空間切成等長條帶；每一條帶內碟 0 佔前 w₀ 個 chunk、碟 1 佔次 w₁ 個 chunk、……
如此長寫在任意整數條帶內，各碟收到的位元組比例嚴格等於權重比。

**Segment（段）**：當各碟容量不同（或某碟容量不足）時，用多個 segment 分段。
每個 segment 有固定的碟集合、權重與邏輯範圍 `[logical_begin, logical_end)`。
例如權重 [6:3:2:1] 的 1 TB 區段後，可接僅含前 3 碟的區段（容量較小的碟退出），
再接到僅含碟 0 的區段（只剩最大碟）。segment 依 `logical_begin` 排序，
核心在 ctr() 驗證：(a) 順序不重疊；(b) 每個 segment 滿足
`stripe_size = Σ weight×chunk` 不變式。

**設計取捨**：為何 segment 而非「依容量全域調整權重」？——各碟權重通常由性能決定
（solo 比），而容量是另一維度；segment 讓「性能權重」與「容量分段」正交，管理者可
獨立調配，也避免全域等權重把容量浪費在已用盡的碟上。

### 3.2.3 映射演算法

```
輸入：邏輯位址 L（byte，自卷起始）
Step 1（選段）：在 segment 陣列中 binary search 找 seg，使
      L ∈ [seg.logical_begin, seg.logical_end)
Step 2（條帶定位）：令 base = L − seg.logical_begin
      stripe_no  = base ÷ seg.stripe_size        （整數除法）
      stripe_off = base mod seg.stripe_size       （餘數）
Step 3（選碟）：累積邊界（僅依賴權重，可在 ctr() 預算或當場算）
      boundary[0] = 0
      boundary[i] = Σ_{j<i} w_j × c
      取 i 使 boundary[i] ≤ stripe_off < boundary[i+1]
Step 4（實體位址）：
      physical_offset = stripe_no × w_i × c + (stripe_off − boundary[i])
      sector = physical_offset >> 9
輸出：(disk i, sector)
```

**推導**：`stripe_no × w_i × c` 是「前面所有完整條帶中，碟 i 已寫入的位元組」；
`stripe_off − boundary[i]` 是「本條帶內碟 i 區段內的偏移」；兩者相加即碟 i 上的
實體偏移。此映射為純四則運算，無記憶體查表、無鎖；選段 O(log m)（m 為段數，
實務 ≤ 3），選碟 O(n)（n 為碟數，實務 ≤ 4，可用 precomputed boundary 化為 O(1)）。

**範例**：權重 [6:1]、c = 1 MB、stripe = 7 MB。

**表 3.2 映射計算範例（權重 [6:1]、chunk 1 MB）**

| 邏輯位址 L | 計算過程 | 結果 |
|-----------|---------|------|
| 0 | stripe_no=0, off=0 ∈[0,6M) | disk0, offset 0 |
| 6 MB | off=6M ∈[6M,7M) | disk1, offset 0 |
| 7 MB | stripe_no=1, off=0 | disk0, offset 1×6M+0 = 6 MB |
| 6 MB + 4 MB = 10 MB | stripe_no=1, off=3M | disk0, offset 6M+3M = 9 MB |
| 7 MB + 6 MB = 13 MB | stripe_no=1, off=6M | disk1, offset 1M + 0 = 1 MB |

![圖 F4 加權條帶映射示意（figs/F4_mapping.svg）](figs/F4_mapping.svg)

> **圖 F4 說明**：權重 [3:1]、c=1 MB、stripe=4 MB 的落點視覺化。每個邏輯 chunk
> 經 (3.1) 落到唯一碟的固定實體 offset；同色為同一 stripe，碟 0 每 stripe 收
> 3 chunk、碟 1 收 1 chunk。

### 3.2.4 邊界案例與不變式

**表 3.3 映射邊界案例**

| 案例 | 行為 | 理由 |
|------|------|------|
| 恰在碟區邊界（off == boundary[i]） | 落入碟 i（左閉右開區間） | 區間定義 `[boundary[i], boundary[i+1])` |
| bio 跨多碟區 | 平行拆分（3.2.6）或 `dm_accept_partial_bio` | 見 3.2.5 |
| bio 跨條帶邊界 | DM 先切半、後半重新 map | `max_io_len = stripe` |
| 寫入長度非 stripe 整數倍 | 餘量 chunk 依公式落入前段碟 | 確定性：餘量也逐 byte 確定 |
| segment 間交界 | binary search 命中後續 segment | segment 不重疊、覆蓋全空間 |

**承重不變式（動它 = 出錯）**：
1. segment 必須按 `logical_begin` 排序、互不重疊、覆蓋完整邏輯空間；
2. 每個 segment 的 `stripe_size` 必須 = `Σ weight×chunk`；
3. Step 4 的 `map.length` 與 `map.offset` 公式必須一致地使用同一權重與 chunk；
4. 跨碟拆分（3.2.5）的邊界計算與 Step 3 的 boundary 必須一致。

### 3.2.5 DM contract 的配合

為讓 DM core 正確處理跨條帶/跨碟區的 bio：

- `dm_set_target_max_io_len(stripe_sectors)`：進入 `map()` 的 bio 長度 ≤ 一個條帶，
  保證任何 bio 至多橫跨一個條帶的邊界。
- `io_hints`：`chunk_sectors = stripe`、`io_min = min(w×c)`、`io_opt = stripe`，
  引導上層以條帶為單位發送大塊 I/O。
- 跨碟區的 bio 用 `dm_accept_partial_bio(bio, len)` 把「塞得進目前碟區的部分」交還
  DM core 重新進入 `map()`，剩餘部分自動繼續——**跨碟拆分主要由 DM 承擔，
  driver 不自己切讀 bio**；僅寫路徑為追求並行吞吐而自行拆分（下節）。

> 為何讀路徑不自行平行拆分？讀拆分便宜（DM 重進 map 即完成），平行拆分是為
> 「寫吞吐」而存在；讀取在深佇列下由多個 bio 自然並行，無需 per-bio 平行拆分。

### 3.2.6 平行寫路徑

當一個 WRITE bio 在單一條帶內橫跨多碟區（`tv_stripe_calc_boundaries()` 算出
`li − fi + 1 > 1`）時，`tv_parallel_submit()` 把 bio 複製為 per-disk sub-bio
平行提交，讓快碟不吃慢碟的拖累：

```
tv_parallel_submit(orig, segments):
    pending = n_sub_bio
    completed = 0
    for each sub: 
        sub = bio_alloc_clone(orig)        // 共享 page，零複製
        bio_advance(sub, 定位到碟區段)
        sub->bi_end_io = tv_parallel_end_io
        submit_bio(sub)
```

**完成語義（恰好一次）**以三件套保證：
- `atomic pending`：追蹤尚未完成的 sub-bio 數；
- `kref`：block（原 bio 的私有資料）的生命週期；
- `cmpxchg(completed, 0, 1)`：**只有最後一個完成的 sub-bio 執行 endio + 停 timer + 放 kref**。

**兩個重要的實作細節**：
- 完成回呼執行於 hardirq：停 timer 必須用 `del_timer()`，**絕不能用
  `del_timer_sync()`**（後者會自旋等待 timeout callback，於 hardirq 內死鎖）；
- 若某 sub-bio 逾時（timer timeout）：以 `kref_get_unless_zero()` 保活 block、
  將該碟標記 DEGRADED、以 `cmpxchg` 完成原 bio，避免無限期阻塞。

**設計取捨**：平行寫路徑是 driver 全權持有的路徑，繞過 DM 的 end_io；其 sub-bio
錯誤不進一般 error 統計，只透過 timeout 標記碟 DEGRADED。這是刻意設計——寫入錯誤
由 badmap（4.3.2）與 DEGRADED 標記處理，而 timeout 本身也是慢碟借調（4.1）的
觸發訊號來源之一。

## 3.3 瓶頸模型與自動權重

### 3.3.1 瓶頸模型（Bottleneck Model）

**定理 3.1**：給定權重向量 W、總權重 ΣW、各碟順序寫入速率 soloᵢ，條帶化寫入之
總吞吐上界為

```
T(W) = min_i ( soloᵢ × ΣW / wᵢ )          … (3.2)
```

**證明**：碟 i 分配到總資料量的 wᵢ/ΣW。若總吞吐為 T，碟 i 承擔的速率為
`T × wᵢ/ΣW`。碟 i 的速率上限為 soloᵢ，故

```
T × wᵢ/ΣW ≤ soloᵢ  ⇒  T ≤ soloᵢ × ΣW/wᵢ   對所有 i
```

因此 `T ≤ minᵢ(soloᵢ × ΣW/wᵢ)`。當**瓶頸碟（使 (3.2) 達最小值之碟）滿載**時
等式成立；權重匹配時所有碟同時滿載，權重失配時非瓶頸碟可能未滿載但等式仍成立。
□□

**推論 3.1（權重匹配 ⇒ 總吞吐 = 各碟之和）**：若權重與 solo 成正比
（∃k, wᵢ = k·soloᵢ），則每一項

```
soloᵢ × ΣW/wᵢ = (wᵢ/k) × ΣW/wᵢ = ΣW/k
```

各項相等，`T = ΣW/k = Σᵢ soloᵢ`。即「權重比 = 速比」時，條帶化把全部碟的
順序速率「加」起來——**這就是 auto_weight 的理論根據**。

**推論 3.2（瓶頸碟識別）**：達成 (3.2) 之 i* 即瓶頸碟；實驗（6.3.1）顯示
排水態 **6:1:1:1 等權** 4 碟場景 `T = D×9 ≈ 1760` 精確命中，D（最慢碟）即瓶頸。

![圖 F5 瓶頸模型幾何示意（figs/F5_bottleneck.svg）](figs/F5_bottleneck.svg)

> **圖 F5 說明**：左半為權重失配（[6:1:1:1]）時各碟的 `soloᵢ×ΣW/wᵢ` 水平線，
> 最矮線即瓶頸（D，只分到 1/9 資料仍把總吞吐壓到 `D×9`）；右半為權重 ∝ solo
> （推論 3.1）時各線重合於 `Σsolo`，無瓶頸碟。圖中數據為示意值（僅說明幾何）；
> 實測對應見 6.3.1（`T = D×9 ≈ 1760`）。

### 3.3.2 auto_weight：窮舉式自動權重

實務上無法先驗得知穩定 solo（受 SLC、插槽、磨損影響），故 `scripts/auto_weight.sh`
以量測驅動求權重：

1. **量測 solo**：對每碟獨立跑 8 G、1 M、libaio、深度 32 的順序寫入，取平均；
   以固定協定量測（排水態或冷態＋60 s 空檔，見 6.1.2），避免 SLC 帶狀誤判。
2. **整數正規化**：以最慢碟 solo 為基準，先估各碟權重 `wᵢ ≈ base × soloᵢ/solo_min`。
3. **窮舉搜尋**：對基底 base ∈ [2, 40]、每權重在 `floor` 與 `ceil` 間 ±1 變異，
   全域列舉候選權重向量；依 (3.2) 計算各候選 `T`，取最大者——等價於「令各碟的
   `soloᵢ×ΣW/wᵢ` 盡量相等、最大化最弱碟利用率」。另有 cap（權重上限 128）
   防止單碟權重過大。
4. **驗證**：以候選權重建卷實測，確認分布精確且吞吐接近模型。

實驗（6.3.2）中 auto_weight 產出的權重使寫入階梯嚴格單調；S2/S3 對模型偏差
±3% 內（S4 -5.9%，枚舉顆粒度，見 6.3.2）；S4 較等權重 6:1:1:1 提升 70.6%
（3006 vs 1762 MB/s），模型上界達 Σsolo 的 99.6%（實測 93.7%）。

**設計取捨**：為何窮舉而非閉式解？——(3.2) 是 max-min 問題，閉式解需量測精準；
但權重必須是整數（chunk 分配以 chunk 為單位），整數空間使「近似速比」與
「精確分布」之間有可搜尋的餘裕，窮舉在 n≤4、base≤40 時空間極小（秒級），
且可納入 cap 等約束，故以窮舉保證最優性。

### 3.3.3 DMI-aware 權重（共用匯流排）

(3.2) 假設各碟獨佔其介面；但 SATA 碟與走 PCH 的 NVMe 碟共用**南橋 DMI 上行頻寬**。
在測量平台，DMI 實測 ~1300 MB/s。若權重按 solo 比例分配（B、C、D 皆走 DMI），
B+C+D 合成流量會超過 DMI 上限而互搶頻寬，實際吞吐遠低於模型（實測比例權重
[64:47:16] 僅 2561 MB/s）。

**修正**：把 DMI 視為一台共享裝置。設 DMI 碟集合 𝒟、CPU 直連碟 A（不經 DMI，
權重 w_A、solo_A）。要求 DMI 碟的權重和受限：

```
Σ_{i∈𝒟} w_i ≤ DMI_Budget × w_A / solo_A      … (3.3)
```

**推導**：總吞吐若以 A 為瓶頸，`T = solo_A × ΣW/w_A`。DMI 碟承擔的速率為
`T × Σ_{𝒟}w_i/ΣW = solo_A × Σ_{𝒟}w_i/w_A`。令其 ≤ DMI_Budget 即得 (3.3)。

代入測量平台（DMI_Budget≈1300、solo_A≈2070，設計期估計值；定案量測
2064，6.1.3）：以 w_A=64 計，`Σ_{𝒟}w_i ≤ 40.2`。
再按各碟 solo 比例分配份額：3 碟取 B:C ≈ 1520:517 縮放得 DMI-aware 權重
**[64:30:10]**；4 碟再依 C:D ≈ 517:223 加回 D，得 **[64:27:9:4]**。
實驗證實 [64:30:10] 達 3370 MB/s，較比例權重 **+32%**；且
`S3_max = solo_A + DMI_Budget ≈ 3364` 精確命中 (3.3) 的預期。
四碟 [64:27:9:4] 亦由實測證實（6.3.1）：B+C+D 合計流量被壓在 DMI 預算內、
瓶頸回歸 A 碟（`solo_A×104/64 ≈ 2064×104/64 ≈ 3354`，實測 3300、-1.6% 偏差）
——(3.3) 是「把共享資源
瓶頸轉回單碟瓶頸」的充分條件，且轉移後模型 (3.2) 重新成立。

**教學涵義**：(3.2) 是「各碟自覺的瓶頸」，DMI 是「共享的瓶頸」。當共享匯流排
成為更嚴格的限制時，權重分配必須以共享資源預算（(3.3)）為主，而非各碟 solo 比例
——這對任何「多碟共用上行匯流排」的系統（南橋、PCIe switch、NVMe-oF 連結）皆適用。

## 3.4 測試架構設計

為兼顧「單元級正確性」與「整合級真實性」，設計四層測試——由底層的確定性驗證，
到最上層的真實硬體吞吐：

**表 3.4 四層測試架構設計**

| 層 | 工具 | 驗證對象 | 環境 |
|----|------|----------|------|
| L1 單元 | `tests/test_map.c`（501 assertion） | 映射公式、權重分布、餘量、確定性 | 使用者態（不需核心） |
| L2 核心模擬 | `tests/test_stripe_kernel.c`（27 項） | 條帶邊界、平行拆分、完成語義 | 使用者態模擬 |
| L3 dmsetup 建卷 | 真實建卷 + `dmsetup status` 計數器 | 分布 byte 精確、err=0、跨 reload | 核心（真實裝置） |
| L4 整合 | fio 基準 + 腳本（borrow_verify/stack_retest/multi_vol_suite…） | 吞吐、模型命中、耐久 | 核心（真實裝置） |

**設計理由**：L1/L2 在使用者態編譯（`make test`），開發迴圈快、能窮舉映射的
邊界案例；L3 的計數器驗證是正確性的關鍵手段——每卷寫完比對各碟 `wr=<bytes>`
與權重的比例，可**逐 byte 證實分布無誤**；L4 才是性能與模型驗證的場所。
三層各司其職，避免「只用 fio 黑箱測、出了錯不知是映射還是裝置問題」。
落地細節見第五章 5.8。

## 本章小結

第三章回答了 P1（加權條帶＋確定性映射）與 P2（性能建模）的**設計**：
- 加權條帶映射 (3.2)：以權重把邏輯空間均分，O(1) 無表、逐 byte 精確、確定性；
- 瓶頸模型 (3.3)：`T = minᵢ(soloᵢ×ΣW/wᵢ)`，權重與 solo 成正比時達 `Σsoloᵢ`
  （推論 3.1），權重可由 `auto_weight` 窮舉求出，並以 DMI-aware 修正處理共享匯流排；
- 測試架構設計 (3.4)：四層各司其職。

P3（權重借調）與 P4（容錯/管理）的設計放在第四章；第五章給出兩章設計的實作，
第六章驗證模型與實作。
