### 5.1.3 核心資料結構（`tieredvol.h`）

```
struct tv_segment {
    u64 logical_begin, logical_end;   // 邏輯範圍（左閉右開，byte）
    u64 stripe_size;                  // = Σ weight×chunk（ctr 驗證）
    u32 disk_count;                   // 參與碟數
    u32 weights[];                    // 權重向量 W
    int policy;                       // -1 繼承 / 0 static / 2 random
    int mirror_disk;                  // seg0_mirror（-1 表示無）
    …  （壞區 bitmap 引用、WC 分組狀態、統計計數）
}

struct tv_meta {
    u32 chunk_size;                   // 分配單位（本論文固定 1 MB）
    u32 n_segments;                   // segment 數（實務 ≤ 3）
    struct tv_segment *segs[];        // 依 logical_begin 排序
    int runtime_policy;               // 全域 policy
    u32 runtime_borrow_watermark_kb;  // 借調水位（KB）
    …   （碟清單、by-id 路徑、統計、borrow 表頭）
}

struct tv_io_stats {
    atomic64_t rd_ops, rd_bytes;      // 讀計數
    atomic64_t wr_ops, wr_bytes;      // 寫計數
    atomic64_t err;                   // 錯誤計數
    atomic64_t in_flight_bytes;       // 借調觸發用水位
}

struct tv_borrow_entry {              // 借調表項目（16 B/entry）
    u32 dst_disk;
    u32 dst_sector;
};
// block_size = chunk_size/8（1 M chunk → 128 KB block）
```

## 5.2 映射與條帶實作

### 5.2.1 `tv_map_logical()` 偽碼

```
tv_map_logical(meta, L) -> (disk, sector):
    seg = binary_search(meta->segs, L)          // L ∈ [seg.begin, seg.end)
    base = L − seg.logical_begin
    stripe_no  = base / seg.stripe_size
    stripe_off = base % seg.stripe_size
    off = stripe_off
    for i in 0 .. seg.disk_count−1:             // 累積邊界找碟
        if off < seg.weights[i] * meta.chunk_size:
            return (i, (stripe_no * seg.weights[i] * chunk_size
                       + off) >> 9)
        off -= seg.weights[i] * meta.chunk_size
```

實作重點：

- 選段用 binary search；`stripe_size` 在 ctr() 算好存於 segment，熱路徑零計算。
- `tv_stripe_calc_boundaries()`（`tieredvol_stripe.c`）依 bio 範圍算出該 bio
  橫跨的碟區間 `[fi, li]`（供平行拆分判斷）。
- `map()` 對單碟區 bio：改 `bi_bdev` + `bi_sector` 後回 `DM_MAPIO_REMAPPED`；
  對跨碟區 WRITE：`tv_parallel_submit()` 回 `DM_MAPIO_SUBMITTED`；
  對跨條帶：`dm_accept_partial_bio()` 交還 dm core 重新映射（driver 不自己切）。
- ctr() 設定 `dm_set_target_max_io_len(stripe_sectors)` 與 `io_hints`
  （`chunk_sectors=stripe`、`io_min=min(w×c)`、`io_opt=stripe`）。

### 5.2.2 `tv_parallel_submit()` 完成語義

三件套保證「恰好完成一次」（3.2.6）：

```
per-block:
    atomic pending = 0          // sub-bio 計數
    struct kref kref            // block 生命週期
    atomic completed = 0

tv_parallel_end_io(sub):        // 每個 sub-bio 完成時（可能 hardirq）
    if atomic_dec_and_test(pending):
        cmpxchg(completed, 0, 1)          // 僅最後一個通過
        endio(orig_bio)                   // 原 bio 恰好完成一次
        del_timer(&timer)                 // 注意：不可用 del_timer_sync()
        kref_put(kref)

timeout_cb(timer):
    if kref_get_unless_zero(kref):
        標記對應碟 DEGRADED
        cmpxchg(completed, 0, 1)
        endio(orig_bio)
        del_timer(&timer)
        kref_put(kref)
```

**兩個承重牆**：(1) 完成語義（kref/timer/`cmpxchg(completed,0,1)`、hardirq 內
`del_timer`）——違反即雙完成/漏完成/死鎖/UAF；(2) 邊界算術——違反即映射錯位、
資料寫錯碟。原始碼層規則（`DESIGN.md`）：改平行路徑或完成語義，必須解釋與
kref/timer 的互動。

## 5.3 權重借調實作

`tieredvol_borrow.c`（441 行）：

- **觸發**：每碟 `in_flight_bytes ≥ borrow_watermark_kb` 且寫入整 block 對齊
  （`block_size = chunk_size/8`）。高負載才借，避免正常路徑查表開銷。
- **選碟**：取最少負載碟（排除自身、DEGRADED、借用區無空間者）。
- **表**：per-block entry `(dst_disk, dst_sector)`（v2 表 16 B/entry、magic 標示）；
  lookup 對讀與重寫（`need==0`）解析同一目的地——**借出去的 block 永遠讀得回來**。
- **一致性**：`borrow_off` 只停新借（lookup 不檢查 enabled）；借用區配置
  all-or-none（整塊）；I/O 提交與表操作同一臨界區。
- **持久化**：remove 時存 `<config>.borrow`，重建載入；跨 reload 位址一致。

實作對照承重牆：改 borrow 一致性（off 仍解析、all-or-none、.borrow 存/載），
會導致資料讀寫錯碟或跨 reload 位址漂移。

```
// 寫入路徑（借調判斷）
tv_map_logical / WRITE 區塊位址 L：
    d = static_map(L)                        // 3.2 的 O(1) 確定性映射
    if disk[d].in_flight_bytes >= watermark 且 L 整 block 對齊:
        dst = 最少負載碟（排除自身/DEGRADED/借用區滿）
        alloc block（全或無）;  lock(borrow_lock)
        write 至 dst.borrow_region
        borrow_tab[L/block].set(dst, sector) // 16 B/entry、magic、v2
        unlock(borrow_lock); endio(orig)
        return                        // 例外路徑完成
    正常路徑：平行/單碟提交（不查表）

// 讀取 / 重寫（need==0）
tv_map_logical / READ or 重寫 L：
    b = borrow_tab.lookup(L/block)
    if b 命中: 解析至 b.dst / b.sector      // 借出閉包：不檢查 borrow_off
    else:      static_map(L)               // 正常確定性映射
```



## 5.4 寫入快取實作

`tieredvol_wc.c`（211 行）：

- 以 `(segment, stripe_no)` 分組，entries 為 linked list，`accumulated` 追蹤累積量。
- **緩衝條件**：`wc_enabled && WRITE && segment 有效 && disk_count > 1`；
  不符回 `-EAGAIN` → 直接路徑。**4 K 小寫（bio < chunk）由此繞過 WC**，
  是 4 K 性能特性的實作根源（6.4）。
- **Flush**：條件與 4.2.2 相同；flush 時 splice entries → batch，每筆重跑
  平行/單碟路徑，且 submit 前 call `tv_mirror_handle()`（保證 mirror 一致）。
- **讀序承重牆**：`bio_data_dir() != WRITE` 時先 `tv_wc_flush()`——違反此
  不變式 = 讀到舊資料。

```
tv_wc_try_buffer(bio):
    if !wc_enabled 或 非 WRITE 或 disk_count<=1:  return -EAGAIN
    依 (segment, stripe_no) 分組入 linked list
    accumulated += bio_size
    if accumulated >= stripe_size: tv_wc_flush()   // 同步
    else: schedule_delayed_work(flush, 1 jiffy)    // 非同步
    return DM_MAPIO_SUBMITTED
```

## 5.5 鏡像與重建實作

`tieredvol_mirror.c`（706 行）：

- **寫**：`tv_mirror_handle()` 以 `bio_alloc_clone()` fire-and-forget 複寫至 mirror
  碟（`mirror_sec = logical − seg_begin`）；mempool（pool size 128）防 OOM；
  `tv_pw_add()` 記 pending；成功/失敗更新 `mirror_write_ops/errors`。
- **讀錯誤重試**：`tv_read_retry_work()` 先 `tv_pw_is_pending()`（最多 32 次 ×
  1 ms 退讓）等 mirror 寫排空，再 clone 自 mirror 重讀；超過即 give-up。
- **rebuild**：kthread 依 static map 逐 chunk「讀 primary → 寫 mirror」；同步
  I/O + `wait_for_completion`；失敗 backoff（10 ms 加倍至 1 s）；每 10 MB 回報進度。
- **rebuild_badmap**：修正 compound page 造成的 `bi_size` 計算 bug；
  壞區重建 `1 recovered, 0 failed`、無 hang。

`tieredvol_badmap.c`（144 行）：per-disk chunk bitmap（`n_chunks = disk_sectors/
chunk`）；壞塊讀 zero-fill、壞塊寫跳過；WRITE 錯誤於完成回呼自動標壞；以
`badmap_<disk>=a-b,c` 持久化於 config，kernel save 時壓縮寫回。

```
// 鏡像寫（fire-and-forget，與 primary 平行）
tv_mirror_handle(bio):
    clone = bio_alloc_clone(mempool)            // pool size 128 防 OOM
    clone 定位至 mirror 碟: mirror_sec = logical − seg_begin
    tv_pw_add(clone)                            // pending ring，供讀重試等待
    submit clone                               // 成功/失敗更新 mirror_write_ops/errors

// 讀錯誤重試
tv_read_retry_work(bio):
    for i in 1..32:
        if tv_pw_is_pending(clone 對應): msleep(1)   // 等 mirror 寫排空
        else: break
    clone 自 mirror 重讀；成功 → 回傳；超過即 give-up

// rebuild（kthread，依 static map 逐 chunk）
rebuild_kthread:
    for chunk in map:                             // 靜態映射，確定性順序
        read(primary) → write(mirror)             // 同步 I/O + wait_for_completion
        失敗 → backoff（10 ms 加倍至 1 s）重試
        每 10 MB 回報進度
```



## 5.6 併發與一致性實作

- pending-write ring：`tv_pw_lock` spinlock 保護；pending-read ring：
  `tv_pending_lock` spinlock、per-CPU lockless。
- ring 滿（full）/遺漏（MISS）與退讓逾時（give-up）皆有明確語義（4.4.2），
  計數器反映於 `err`。
- 熱路徑（映射、單碟提交、WC 緩衝）**無共享鎖**；唯一共享 spinlock 在
  錯誤/完成冷路徑——多卷併發實驗（6.2.3）由此得益（±2% 孤立）。

## 5.7 設定、管理與計數器實作

- `tieredvol_meta.c`（749 行）：INI parser + CRC32C 驗證；ctr() 對非法參數
  fail-closed（被移除的 adaptive policy 值、越界權重、重複碟、mirror 與 primary
  重疊、segment 順序錯誤等）；kernel save 先寫 `.bak`。
- `tieredvol_sysfs.c` + `tieredvol_msg_*.c`：sysfs 屬性（如 `policy` 唯讀）、
  `dmsetup message`（set_policy、set_seg_policy、borrow_off、mirror、stats、
  config）。
- 統計：每碟 `wr=/rd= ops/bytes`、`err`、borrow/mirror 計數，供 `dmsetup status`
  驗證分布（第六章正確性判據）。

## 5.9 複雜度與成本總覽

各路徑的時空成本收束如下（設計對應：3.2.6、4.1、4.2、4.3）：

| 路徑 | 時間複雜度 | 空間/成本 | 說明 |
|------|-----------|-----------|------|
| 熱路徑映射 | O(1)（選段 O(log m)，m≤3） | 無表、無狀態 | 純算術；boundary 預算後選碟 O(1) |
| 平行拆分 | O(n)，n=碟數≤4 | per-block atomic/kref | 每碟 1 sub-bio（3.2.6） |
| borrow lookup | O(1) 查表 | per-block 16 B/entry（v2） | 僅被借出 block 走查表 |
| borrow 寫入 | O(1)＋借用區配置 | 借用區 over-provisioning | 例外路徑，僅少數整塊寫入 |
| WC 緩衝 | O(1) append | 累積至 stripe_size 記憶體 | 以延遲落碟換合併效率 |
| WC flush | O(batch) | batch 峰值記憶體 | 與直接提交共用平行/單碟邏輯 |
| mirror 寫 | O(1) clone | mempool pool 128 | fire-and-forget，與 primary 平行 |
| rebuild | O(總資料量) | 單 chunk 緩衝 | kthread、backoff 重試、每 10 MB 進度 |
| rebuild_badmap | O(壞區 chunk 數) | per-disk badmap bitmap | 壓縮寫回 config |

> 取捨總結：**正常路徑全部 O(1) 且無共享鎖**（性能宣稱 G2）；所有「動態機制」
> （借調、WC、mirror、重建）的成本都集中在**異常或初始化路徑**，不影響熱路徑
> 吞吐——這是 6.2.3 多卷併發 ±2% 孤立的實作基礎。

## 本章小結
